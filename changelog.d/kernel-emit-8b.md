kind: `vulkane-spirv-emit`: `Backend::lower_kernel` first slice (workgroup memory, barriers, fences)
---
`SpirV::lower_kernel` lowers integer (`I32`/`U32`) kernel-layer kernels: buffer parameters (one storage buffer each, `Read` buffers `NonWritable`), static `Shared` arrays as `OpVariable Workgroup`, thread, block, `BlockDim` and `GridDim` ids, locals, `Let`/`Load`/`Assign`/`Store`, `Barrier { Block | Subgroup, Full }` as `OpControlBarrier` (semantics `AcquireRelease | WorkgroupMemory | UniformMemory`, the buffer class added to the ROADMAP's text because a CUDA `__syncthreads()` orders global writes too) and `Fence` as `OpMemoryBarrier` (`SeqCst` collapses to `AcquireRelease`). Everything else (floats, dynamic `Extent::Param`, control flow, atomics, device or named barriers, scalar parameters) is a typed `UnsupportedKernel` naming it; the by-name patent declines still come first. ROADMAP rows 8a and 8b are partly done (see their rows). Verified: `spirv-val --target-env vulkan1.1` on every emitted module (it caught a doubly decorated stride and block while this was written), a structural control (the module without the barrier has no `OpControlBarrier`), and a device test that reverses a 256-element block through shared memory exactly with the barrier; without it 128 of 256 cells differed on the test device (reported, not asserted: a missing barrier is a race and a device may still come out right).
